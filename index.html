1. 安全与加密 Security & Encryption

对称 vs 非对称加密 / Symmetric vs Asymmetric

对称 Symmetric (DES/AES)非对称 Asymmetric (RSA)
密钥 Keys单一共享密钥 one shared secret key公钥+私钥 public/private key pair
速度 Speed快 fast（约快 100–1000 倍）慢 slow
密钥分发 Key distribution困难（需安全传给对方）hard公钥可公开分发 easy
用途 Use大文件/会话数据加密 bulk data密钥交换、数字签名 key exchange, signature

✔ 真题 A1：对称加密优点 = (i) 只知算法不足以解密 + (iii) 更快 → E。注意 (ii) "无需密钥" 和 (iv) "无需分发密钥" 都是错的——对称加密恰恰需要密钥且要分发。

哈希函数 Hash Function

把任意长消息变成固定长度摘要（digest），单向、不可逆。用于完整性 integrity 与数字签名。常见：MD5、SHA 系列。

One-way function turning a long message into a fixed-length digest; used for integrity and digital signatures.

数字签名与 PKI / Digital Signature & PKI

签名 = 用发送方私钥加密消息的哈希；接收方用发送方公钥验证。提供身份认证 authentication、完整性 integrity、不可否认性 non-repudiation。PKI 由 CA（证书机构）签发证书绑定"身份↔公钥"。

Signature = hash of message encrypted with the sender's private key; verified with the sender's public key. Provides authentication, integrity, non-repudiation. PKI: Certificate Authority binds identity to public key.

  • 机密消息（David→Ann）：用Ann 的公钥加密 → 只有 Ann 的私钥能解
  • 签名消息（Ann→David）：用 Ann 的私钥签哈希 → David 用 Ann 公钥验
  • 实际系统 = 混合：对称密钥加密数据 + 非对称传密钥（如 TLS/SSL）

双因素认证 2FA / Two-Factor Authentication

组合两种不同类别的凭证：知识 factors（密码/PIN）+ 持有 factors（手机/智能卡/OTP token）+ 生物 factors（指纹/面容）。实现举例：密码+短信验证码、密码+TOTP（Google Authenticator）、ATM 卡+PIN、密码+U2F 安全钥匙。

Combining two different categories of credentials: knowledge (password), possession (phone/smart card/OTP), inherence (biometrics). E.g. password + SMS OTP, ATM card + PIN.

2. 网络与移动通信 Networks & Mobile Communications

防火墙 Firewall

功能：按源/目的地址过滤 IP 包；作为所有外部通信必经的瓶颈点（choke point）保护多台服务器；限制本地用户访问外部。❌ 不备份文件。

WiFi 安全风险与对策 / WiFi Risks & Countermeasures

风险 Risks
  • 窃听 eavesdropping（开放信道）
  • 假冒 AP / evil twin 恶意热点
  • 中间人攻击 MITM
  • WEP/WPS 弱加密被破解
  • 未授权接入盗用带宽、ARP 欺骗
对策 Mitigation
  • 用 WPA3/WPA2-AES，禁用 WEP/WPS
  • 关闭 SSID 广播 + MAC 过滤
  • VPN / HTTPS 端到端加密
  • 强密码、定期换密钥
  • 入侵检测 IDS + 静态 IP / 802.1X 认证

蜂窝网络容量 / Cellular Capacity（真题 B9/B10）

提高容量四法：① 新增信道 adding new channels；② 小区分裂 cell splitting；③ 小区分区/扇区化 cell sectoring；④ 微小区 microcells。

GSM 频率复用 / Frequency Reuse（真题 A5）

复用簇从 4 信道扩到 7：同频干扰↓、信噪比↑、定位更准（更多基站/信号）；但需要更多频谱而非更少 → 答案 D。

TD-SCDMA 特色 / Unique Features（真题 B7/B8）

  • 时分双工 TDD（上下行同频分时隙，不对称业务高效）
  • 智能天线 smart antenna（波束赋形 beamforming）
  • 同步 CDMA（上行与基站同步，降低干扰）
  • 中国自主 3G 标准（答任意两条即可）

IPv6 vs IPv4（真题 C2a）

① 128 位地址（几乎无限）vs 32 位；② 内置 IPsec 安全支持；③ 无需 NAT，端到端连通；④ 简化头部、路由更快；⑤ 内置支持移动性 MIPv6 与自动配置 SLAAC；④ 组播与流标签 QoS 更好。

128-bit address space, built-in IPsec, no NAT (end-to-end), simplified header, better mobility & auto-configuration, flow label for QoS.

技术场景 Scenario关键词

被动 RFID 工作原理（真题 C2d 答题要点）

① 读写器通过天线发射射频载波询查信号；② 标签天线接收能量，整流供电唤醒芯片；③ 标签将存储的 EPC/数据以反向散射调制（backscatter）发回；④ 读写器解码后传给后台系统处理；多标签用防碰撞算法（如 ALOHA）分时应答。

Reader broadcasts RF inquiry → passive tag harvests energy, wakes chip → tag replies by backscatter modulation → reader decodes and passes data to backend; anti-collision (ALOHA) handles multiple tags.

传感器 Sensors（真题 B1）

压电效应 piezoelectric effect → 加速度计 accelerometer（也用于陀螺仪类 MEMS 振动传感）。其他常考：GPS（位置）、电子罗盘 magnetometer（方向）、光敏、接近传感器。

4. 支付、供应链与新兴应用 Payment, SCM & Applications

支付卡 / Smart Card vs Magnetic Stripe（真题 A6）

正确说法：(i) 智能卡更安全 ✔、(ii) 磁条卡靠铁磁颗粒存储 ✔ → 答案 C。错误：智能卡数据不能被磁铁擦除（ EEPROM，非磁性存储）；智能卡需电源（由读卡器接触供电）；并非所有智能卡都内置电池。

在线支付网关 Online Payment Gateway（真题 C4c 答题框架）

画图要素：客户 → 商户网站 → 支付网关 → 收单行/银行卡网络（Visa/Master） → 发卡行。流程：① 顾客下单，加密（SSL/TLS）提交卡信息；② 网关验格式、防欺诈检测；③ 通过收单行转发至发卡行授权（3-D Secure 可选验证）；④ 授权结果回传商户，完成扣款结算（清算 settlement）。网关 = 商户与银行间的安全通道。

Customer → merchant site → payment gateway → acquirer → card network → issuer bank; encrypted card data, fraud check, authorization, settlement. Gateway is the secure bridge between merchant and banking network.

牛鞭效应 Bullwhip Effect（真题 C2b/c）

定义：需求信息沿供应链上游传递时被逐级放大扭曲，导致库存波动加剧（3 分核心句）。成因：需求预测修正、批量订货、价格波动促销、博弈性短缺订货。

缓解技术（5 分）：① EDI / API 实时共享销售数据（POS 直连）减少信息延迟；② CPFR 协同计划预测补货；③ RFID/条码实时库存可见性；④ VMI 供应商管理库存；⑤ 电子商务平台直接连接降低中间层级。

VR vs AR（真题 C1a）

VR 虚拟现实AR 增强现实
环境完全虚拟、沉浸式 fully immersive, synthetic真实世界 + 虚拟叠加 real world + overlay
设备HMD 头显、手柄（HTC Vive）手机、轻量眼镜（Pokémon GO、Hololens）

应用游戏、培训、虚拟看房导航、试妆/试穿、维修指引

病毒与安全事件 Viruses（真题 C3c 模板）

以 WannaCry 为例：蠕虫型勒索软件 ransomware，利用 Windows SMB 漏洞（EternalBlue）自动传播，加密文件索要比特币赎金。预防：及时打补丁、关闭不必要的 SMB 端口、离线备份、防病毒软件、不点可疑附件、网络分段。答题时套用"病毒类型 + 传播机制 + 危害 + 防护措施"四段式。

高频答疑 FAQ / 常见疑问解答

Q1：选择题里 (i)(ii)(iii) 组合题总是选错怎么办？ / How to handle combination MCQs?

逐条独立判断 True/False，再对照选项组合，不要整题"感觉"。注意干扰项常把对称/非对称、主动/被动 RFID 的特性互换。✔ 技巧：先找出明显错误的那一条（如"无需密钥"），排除含它的所有选项，通常只剩 1–2 个。

Q2：Part B 简答题要写多长？ / How long should Part B answers be?

题目明确说 "a word or a phrase"——只写一个词或短语（如 RFID、Firewall、Hash function），写多了不加分还浪费时间。考的是"场景→技术"的条件反射，见知识板块第 3 节的映射表。

Q3：Part C 大题怎么拿满结构分？ / How to score in Part C?

① 题目要求 diagram 就一定要画图（PKI、支付网关、RFID），图中标注主角与箭头方向；② 分点作答 (a)(b)(c) 对应小问分值；③ 定义题先一句话定义再展开；④ 遇到没学过的新技术（如 WannaCry），套用通用知识框架回答，展示"知识更新能力"可拿 bonus。

Q4：对称加密更快，为什么还要非对称加密？ / Why asymmetric if symmetric is faster?

因为对称加密的致命问题是密钥分发（怎么安全地把密钥给对方？）和无法实现数字签名/不可否认。所以实际系统（TLS）用非对称交换会话密钥，再用对称加密传输数据——各取所长。

Q5：GPS、北斗、RFID、Cell-ID 到底怎么选？ / Which positioning tech when?

户外实时连续追踪车辆→GPS；中国卫星导航+短报文+信号经地面站中转→北斗；仓库/包裹/物品级识别追踪→RFID；室内低精度、只要手机不装额外硬件→Cell-ID/基站定位；要快又准→A-GPS。

Q6：Bullwhip effect 答题的标准句式？ / Standard phrasing?

定义（3 分）："The variability of orders/demand is amplified as it moves upstream in the supply chain, causing increasing inventory swings from retailer→wholesaler→manufacturer." 缓解（5 分）必须写"技术 + 如何缓解"：EDI 共享 POS 实时数据（减少信息失真与延迟）、RFID 提供库存可见性、CPFR/VMI 协同机制。

Q7：还有哪些可能的考点这次真题没考？ / Other likely topics?

按 ELEC6098 大纲，历年还考过：电子商务模式（B2B/B2C/C2C）、电子现金/电子钱包/微支付、SET 协议、移动商务 LBS 应用、蓝牙/ZigBee/NFC 比较、4G/5G 特性、CRM/ERP、网络营销、区块链与加密货币、伦理与隐私。复习优先级：安全（每年必考）> 定位技术 > 支付 > 供应链 > 新兴应用。

Chapter 1 · Introduction & B2C（intro and B2C -2026.pdf，71 页）

  • 驱动电子商务的 3 大力量 3 main forces：① Economic forces 经济力量（降低成本 cost reduction）② Marketing & Customer Interaction forces 营销与客户互动（线上展示、分享更多产品信息）③ Technology & Digital Convergence forces 技术与数字融合（行业融合，如 Apple 卖 iBook、Amazon 卖 Kindle、PayPal 电子交易）。Climate forces 是干扰项。

Chapter 2 · B2B & RFID（原 PDF 加密，以下要点来自 Kahoot 官方题库）

  • 牛鞭效应 Bullwhip Effect：消费者需求小变化 → 上游订单大波动（注意方向：向零售端移动时需求变化性减小）；可用 RFID 和共享信息缓解；不共享信息时累积效应是相乘 multiplicative 的；最重要的共享信息是 销售数据 sales data。
  • 外包订单履行 Outsourced order fulfillment 提供的关键服务：仓储 storage、包装配送 packing & delivery、库存管理 inventory management、订单追踪 order tracking、客服处理。不做：产品制造、定制软件开发、员工招聘。
  • EDI 优点：减少人工与纸张、降低单据处理成本；不是优点："比传统方法增加处理时间"、"对纸质单据也提升效率"。
  • 主动 RFID 标签优点：读取距离长、可加传感器（成本更高、要换电池——非优点）。

Chapter 3 · Enabling Technologies（Enabling Technologies 2025.pdf，90 页）

  • 加速度计 Accelerometer：阻尼质量块+弹簧模型，测加速度的大小与方向 → 姿态 orientation、振动 shock、跌落检测；手机自动横竖屏、Wii 手柄、相机防抖、硬盘跌落保护、ACN 碰撞自动呼救。
  • 陀螺仪 Gyroscope：高速转子角动量+角动量守恒，测旋转/角速度。压电效应 piezoelectric 把压力转成电信号；Draper 音叉陀螺 vs 压电陀螺：前者不受温度影响、灵敏度更高。
  • ⭐ 判断题陷阱：匀速圆周运动加速度计测不到、陀螺仪测得到；陀螺仪才基于角动量守恒；两者结合测姿态（惯性导航 Inertial Navigation：无需 GPS，从最后已知位置推算）。
  • 隧道里追踪车辆位置用什么？→ 加速度计（惯性导航）（GPS 隧道无信号）。
  • 场景选技术：跟踪包裹 → RFID；跟踪救护车 → GPS；Apple Pay 用到的技术 → NFC + 生物识别 Biometric。
  • AR 是 exterior view（从内向外看），VR 是沉浸式向内看。
  • LBS 应用：紧急呼叫、目标广告、好友列表、交通天气、包裹/火车车厢追踪。

Chapter 4 · Data Security（原 PDF 加密，以下要点来自 Kahoot 官方题库）

  • DDoS：目标是压垮服务破坏可用性 overwhelm availability（不是偷数据）；"大量请求使服务器过载" → DDoS。
  • Phishing 钓鱼：诱骗个人泄露信息。
  • Web-jacking 网站劫持：把用户重定向到恶意站点/内容被篡改。
  • Server break-ins：利用漏洞非法入侵获取权限。
  • Cookies：存储用户偏好与会话信息。
  • 主动内容 Active content：视频/动画等交互元素，可触发自动行为（静态图文不算）。

Chapter 5 · Mobile Payment（原 PDF 加密，以下要点来自 Kahoot 官方题库）

  • 智能卡 vs 磁条卡：智能卡更安全✔、磁条卡靠铁磁颗粒存数据✔；智能卡数据不能被磁铁擦除、两种卡都需要电源。
  • 手机 NFC 读八达通余额 → Reader/writer mode 读写器模式（不是卡模拟 Card emulation——那是手机当卡刷）。
  • ⭐ 在线支付信息流（必背）：EShop → Payment Gateway → EShop's Bank（收单） → Issuing Bank（发卡） → 原路返回 Payment Gateway → EShop。
  • 在线支付流程包含：Authorization 授权、Merchant identity verification 商户身份验证、Payment gateway verification、User identity verification。
  • 移动签名 Mobile signature：在 SIM 卡上用用户私钥生成的数字签名；待签文本经安全连接送到 SIM 卡；用户需输入 PIN 码。

Part 2 · Cloud / Big Data / AI（Dr. Victor Ng 4 讲）

  • 云计算（NIST 定义）：3 服务模型 + 4 部署模型 + 5 本质特征。
    5 大特征：① On-demand self-service 按需自助 ② Broad network access 广泛网络接入 ③ Resource pooling 资源池化（多租户 multi-tenant）④ Rapid elasticity 快速弹性 ⑤ Measured service 可计量服务。
    3 服务模型：SaaS（用应用，如 web 邮箱）/ PaaS（部署自己的应用，用提供商的语言和工具）/ IaaS（租算力/存储/网络，自己装 OS 和应用）。
